# Read Along — передаточный журнал проекта

Документ для продолжения работы в Claude Code на ноутбуке Владимира. Составлен 19 ноября 2026 по итогам сессии в чате Claude (18–19 ноября 2026). Здесь всё, что сделано, решено и что осталось.

---

## 1. О проекте коротко

**Read Along** — приложение для iPhone. Человек читает вслух простой английский рассказ, приложение слушает и по каждому правильно прочитанному слову двигает рисованный мультфильм. Ошибся (неправильное похожее слово или пропуск) — большой красный крест и звук «бам», строка читается заново. Молчание и посторонняя речь ошибкой не считаются.

Цель — приучить детей и взрослых читать: мама читает ребёнку, ребёнок смотрит мультик, потом пробует сам. Первая версия рассчитана на взрослого, который учит английский.

**Кто что делает:**
- **Владимир** — заказчик, проверяет на своём iPhone, принимает решения.
- **Натаха** — другой ИИ. Делает рассказы, сценарии, видео и пакеты рассказов, ведёт ТЗ.
- **Claude** — делает приложение. Не придумывает рассказы и не меняет тексты в пакетах.

## 4. Хронология решений

1. **ТЗ v1.1 → вопросы.** Claude прочитал первое ТЗ и задал вопросы: синхронизация, формат видео, крест, поля манифеста, язык.
2. **Платформа — iPhone.** Сайт в Safari на iPhone не годится: после проигрывания видео или звука микрофон в Safari перестаёт слышать. Выбран **Expo (React Native) + expo-speech-recognition**.
3. **Бесплатная установка без Apple Developer ($99/год).** IPA собирается на GitHub Actions на macOS без подписи, а Владимир ставит его через **Sideloadly** со своим Apple ID. Ограничения: работает 7 дней, потом переустановка; не больше 3 таких приложений. Репозиторий открытый (так бесплатны минуты macOS) — Владимир согласен.
4. **Синхронизация по каждому слову.** В manifest.json для каждого слова указана секунда (`words[].t`), видео доигрывает до отметки прочитанного слова и ждёт.
5. **Молчание ошибкой не считается.** Правило «пауза 4 с = ошибка» убрано. Добавлена кнопка **Pause Microphone**. Посторонняя непохожая речь пропускается.
6. **Длинные рассказы** (до 10–15 минут) и запоминание места чтения: «Continue from sentence N or start over?».
7. **Весь интерфейс только на английском.** Кнопки: Start / Listening, Pause Microphone, Start Over, Choose a Story, Add Story, Read Again, Skip Sentence.
8. **Крест рисует само приложение.** В пакете только звук `error-bam.mp3`.
9. **Строгость** хранится в настройках приложения (Easy / Normal / Strict), а не в манифесте.
10. **Рассказ заменён на «сон».** Натаха сделала мультфильм по устному рассказу Владимира: мальчик идёт играть, лес, домик, окно, дверь, камин, засыпает на кровати и просыпается дома — это был сон. 14 предложений, сегменты S01–S14. ТЗ обновлено до v1.5–1.6.
11. **Сжатие пакетов.** Без звука, 24 к/с, CRF 27, картинка первого кадра `.jpg` рядом с каждым видео, пакет до 20–25 МБ. ZIP Владимир прикрепляет прямо в чат.
12. **Add Story** — добавление рассказа на телефоне: ZIP из «Файлов» или ссылка.
13. **Загрузка рассказа целиком** при открытии; Start неактивна до конца загрузки. По полоске бегут мальчик и девочка (ролик Натахи `loader-running.mp4`: 512×512, ~3 с, бег на месте на белом фоне; Claude вырезает ровную петлю).
14. **Правило 3 дней.** Файлы мультфильма удаляются с телефона, только если рассказ не открывали 3 дня; после The End сразу НЕ удаляются (мама прочитала — ребёнок попробует сам). Рассказ всегда остаётся в списке.
15. **Темп мультфильма не подгонять под чтение.** Владимир отказался ускорять видео, когда читающий обгоняет мультик: темп мультика задаёт сам мультик.
16. **Непрерывное распознавание** (сборка 2): переход на новое распознавание Apple — SpeechAnalyzer (подробнее в разделе 6).

## 5. Веб-демо (index.html) и что на нём выяснили

Веб-демо делалось, чтобы быстро проверить идею на телефоне без установки. Открывается по ссылке GitHub Pages. Ссылка на страницу Claude не годится: там микрофон запрещён.

Что выяснили на iPhone (это важно и для будущих решений):
- **Видео в браузере глушит микрофон.** Даже беззвучное видео на iOS перехватывает звуковую сессию, и распознавание замолкает без ошибки. Решение в демо — мультфильм показывается кадрами из `*.sprite.jpg` на холсте (режим «Frames»), без видеоплеера.
- **Safari распознаёт речь, только если на iPhone включены Siri или Диктовка.** Chrome на iPhone работал.
- **Web Speech API на iOS работает отрывками**: после каждой фразы останавливается. В демо стоит режим «по фразе» с перезапуском, а при каждом перезапуске браузер показывает плашку о микрофоне. Как в Zoom (одно разрешение на всю вкладку) сделать нельзя: Zoom берёт сырой звук (getUserMedia), а распознавание речи на iOS — отдельная сессия микрофона. Чтобы веб-версия слушала непрерывно, нужно брать звук через getUserMedia и распознавать самим (облачный сервис или модель в браузере). Решили веб-версию оставить как есть, основное — приложение.
- В демо есть журнал отладки, Copy log, переключатели в Settings.

## 6. Приложение: как устроено

**Стек:** Expo SDK 58, React Native, TypeScript. Навигация — простое состояние в `App.tsx` (без expo-router). Библиотеки: expo-video, expo-audio, expo-speech-recognition, expo-file-system (новый API: `File`, `Directory`, `Paths`), expo-document-picker, @react-native-async-storage/async-storage, expo-keep-awake, react-native-safe-area-context, jszip.

### 6.1 Библиотека рассказов (`src/library.ts`, `src/Library.tsx`)
- При открытии приложение читает каталог `stories.json` с GitHub Pages, по нему — `manifest.json` каждого рассказа, сохраняет манифест и обложку.
- Файлы хранятся в `Documents/stories/<id>/…`.
- **Add Story:** ZIP из «Файлов» (распаковка через jszip, ищется `manifest.json`, проверяются файлы) или ссылка (на `.zip` или на папку с `manifest.json`).
- Удаление рассказа — долгое нажатие на карточку.
- **Правило 3 дней** (`cleanupOld`): при открытии списка удаляются видео и звуки рассказов, которые не открывали 3 дня (время открытия хранится в AsyncStorage `opened_v1`). Касается только рассказов из интернета (`remoteBase`). Рассказы из ZIP не трогаются: скачать их заново неоткуда.

### 6.2 Экран чтения (`src/Reader.tsx`)
- При открытии: если файлов нет — `downloadAll` с полоской загрузки (`Loader.tsx`), кнопка Start неактивна; при обрыве — Try Again.
- Видео: один плеер expo-video, без звука; по таймеру 50 мс доигрывает до `target` (секунда последнего прочитанного слова) и ставит на паузу. После последнего слова сегмент доигрывает до конца, и включается следующий.
- **Звуковая сессия iPhone `playAndRecord`.** В коде expo-video (`ios/AudioSessionPolicy.swift`) есть проверка: если сессия уже `playAndRecord`, плеер её не меняет, иначе пропал бы микрофон. Поэтому приложение выставляет `playAndRecord` сразу (expo-audio `setAudioModeAsync({allowsRecording:true})` и `setCategoryIOS`).
- Крест — два повёрнутых красных прямоугольника поверх видео на 1 с, плюс звук `error-bam.mp3` (настройка «Error sound»).
- Пауза микрофона, Start Over, Skip Sentence (после 3 ошибок подряд), The End со счётчиком ошибок, Read Again, запоминание места (AsyncStorage `pos_<id>`).
- **Журнал отладки** на экране (Settings → Debug log), кнопка **Share log** — отправить журнал текстом.

### 6.3 Распознавание речи
- **Новое, по умолчанию (сборка 2):** собственный модуль `app/modules/live-transcriber` на Swift. Работает на SpeechAnalyzer + SpeechTranscriber (iOS 26+, у Владимира iOS 27). Один AVAudioEngine с конвертером формата подаёт звук в анализатор всю сессию — без перезапусков между фразами, распознавание на телефоне. При первом запуске iOS может скачать языковую модель (`mic state: downloading-model`). События в JS: `onResult {text, finalizedText, isFinal}`, `onState`, `onError`. API подсмотрено в библиотеке expo-speech-transcriber: она поддерживает SpeechAnalyzer только для файлов, а живой звук там идёт через старое распознавание, поэтому написан свой модуль.
- **Старое (запасное):** expo-speech-recognition (SFSpeechRecognizer). После каждой паузы выдаёт итог и останавливается, приложение перезапускает его; есть страховка «10 с без слов → перезапуск». Переключатель: **Settings → Speech recognizer → New (continuous) / Old (phrase by phrase)**. Если новое не стартует, приложение само переходит на старое.
- Минус нового: длинная модель SpeechTranscriber не принимает подсказки-слова (contextualStrings), старое — принимает.

### 6.4 Проверка чтения (`src/match.ts`)
- **Почему переделано.** Журнал Владимира показал: телефон сначала слышит «on a», а через пару секунд исправляется на «one day». Старая проверка судила по первому черновику и ставила ложный крест.
- **Сейчас так, как делают тренажёры чтения.** Вся услышанная фраза выравнивается по тексту предложения (Левенштейн по словам: ok / замена / пропуск / лишнее слово, похожесть слов по написанию и звучанию).
  - `readPrefix` — сколько слов подряд с начала прочитано: они сразу подсвечиваются, видео двигается.
  - `findMistake` — крест только по **устоявшемуся** тексту: финализированный распознавателем или не менявшийся 1,5 с. Ошибка — если неверное или пропущенное слово уже «перепрыгнуто» более поздним верным, или если читающий остановился на похожем, но неверном слове.
  - Лишние слова (повторы, «эээ», чужой разговор) не наказываются.
  - Easy прощает пропуск служебных слов (a, the, and…).
- Пороги похожести: Easy 0.6, Normal 0.72, Strict 0.88; «похожее неверное» — от 0.55.
- Проверено на фразах из журнала: «on a boy was when» → ждёт без креста; «one day a toy goes» → ошибка на «boy»; «one day boy goes out» → пропуск «a»; «… what time is it» → пропускается.

## 7. Сборка IPA (без Mac)

Файл `.github/workflows/ios.yml` запускается при каждом push в `app/**` или вручную (Actions → Run workflow):
1. macOS, последний Xcode, Node 22, `npm ci` в `app/`.
2. `npx expo prebuild --platform ios --clean` (папки `ios/` и `android/` не хранятся в git).
3. `pod install`, затем `xcodebuild archive … CODE_SIGNING_ALLOWED=NO`.
4. Упаковка `Payload/*.app` → `ReadAlong.ipa`, артефакт и **GitHub Release** `build-N` (последняя всегда по ссылке `releases/latest/download/ReadAlong.ipa`).
- Сборка занимает около 9 минут. Сборки: build-1 (первая версия), build-2 (непрерывное распознавание, новая проверка, загрузка, правило 3 дней).

**Проверка перед push (локально, в `app/`):**
```
npm install
npx tsc --noEmit
npx expo export --platform ios --output-dir /tmp/expo-check
```
Сам Swift-модуль локально на Windows не проверить — только сборкой на GitHub.

## 8. Установка на iPhone (как сделали)

**Один раз на ноутбуке Windows** (всё уже стоит):
- iTunes и iCloud — версии **с сайта Apple, не из Microsoft Store**. iTunes 12.13.12.3, iCloud 7.21.
- **Apple Mobile Device Support 19.4.0.10** доставлен отдельно через winget: iTunes его не поставил, и из-за этого Sideloadly и iTunes не видели телефон, хотя Windows открывала его как диск. После установки появилась служба **Apple Mobile Device Service** (Running, Automatic).
- Sideloadly 0.60.0 (окно показывает v0.72) — файл с sideloadly.io, проверен Microsoft Defender. Пакет winget не подошёл: хеш не совпал, каталог отстал.
- Сообщение «mdnsNSP.dll is blocked from loading into the Local Security Authority» (Bonjour) — безвредно. Это защита LSA в Windows 11 24H2+, нажать Cancel.
- После установки iCloud нужна перезагрузка (код 3010).
- Окно входа iCloud после перезагрузки — Cancel, входить не нужно.

**Каждая установка или обновление:**
1. Скачать `ReadAlong.ipa` по ссылке из раздела 2.
2. Подключить iPhone кабелем, разблокировать, на телефоне «Trust» (Доверять). Окно автозапуска Windows закрыть.
3. Открыть Sideloadly, перетащить IPA, в iDevice выбрать «iPhone (Владимир)», ввести Apple ID и нажать Start; пароль и код вводит сам Владимир.
4. Один раз (уже сделано): **Settings → Privacy & Security → Developer Mode** → On → Restart → Turn On. **Settings → General → VPN & Device Management** → своя почта → Trust.
5. Через 7 дней приложение перестаёт открываться — повторить шаги 1–3. Режим разработчика включать заново не нужно.

## 9. Что осталось сделать

1. **Проверить build-2 на iPhone.** Непрерывное распознавание, новая проверка, загрузка. Получить журнал (Settings → Share log).
2. **Вставить ролик бегущих детей.** Скачать `loader-running.mp4` из Google Drive, вырезать ровный цикл бега (найти кадр, наиболее похожий на первый, обрезать, при желании сделать фон прозрачным или белым под цвет полоски) и положить в `app/assets/loader-running.mp4` вместо заглушки.
3. **Заменить рассказ на пакет Натахи.** Распаковать `story-001-the-house-in-the-forest.zip` (25 МБ) в одноимённую папку в корне репозитория. В нём её отметки слов, сжатое видео, настоящие «бам» и финальный звук. Проверить manifest.json (14 сегментов, у каждого слова есть `t`, все пути существуют). Файлы `*.sprite.jpg` нужны только веб-демо: оставить или пересоздать.
4. **Журналы на GitHub автоматически** (предложено, Владимир ещё не решил). Приложение после сессии отправляет журнал в Cloudflare Worker, а Worker с секретным токеном GitHub кладёт его в `logs/` репозитория. Напрямую из приложения писать на GitHub нельзя: токен окажется в открытом IPA. У Владимира есть Cloudflare (домены fixtorllc.com, kosmalis.com; Render закрыт).
5. **Хостинг рассказов.** В ТЗ написано «Cloudflare», а сейчас рассказы и каталог лежат на GitHub Pages. При росте библиотеки (100–200 рассказов по ~20 МБ) перенести на Cloudflare R2/Pages и поменять `CATALOG_URL` в `src/library.ts`.
6. **Наблюдать:** служебные слова («a», «the») распознаватель иногда теряет — в Normal это крест (в Easy прощается); акцент — «one day» → «on a».

## 10. Как работать с Владимиром (обязательно)

- **Режим обсуждения по умолчанию.** Ничего не делать (файлы, код, команды, установки), пока он явно не скажет «делай», «начинай» или «приступай». Когда кажется, что всё ясно, спросить: «Все вопросы закрыты, начинать?» — и ждать.
